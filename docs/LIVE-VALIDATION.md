## REST 生命周期

已经实际执行 CCI 应用及端口 Service 创建、复制、停止、删除；ACP 创建、复制、停止、删除；DNAT 创建、绑定、迁移、删除。操作前后核对 UID 和当前用户归属，未改变原有规则。

实际请求发现并修复两项问题：ACP 复制不能同时提交 total_replicas 与每规格 replicas；无端口 CCI 的 GetService 会返回空 UID 的虚拟视图，无需删除。ACP 停止异步耗时可能超过 90 秒，现有轮询窗口已延长。

先前使用启动时安装 sshd 的镜像未能通过公网入口登录，因此不能将控制请求成功等同于 SSH 可用。新镜像的云端验收见后续记录。

## SSH 镜像

`nvcr.io/nvidia/pytorch:25.06-py3` 增加 OpenSSH 后已在本机成功构建为 linux/amd64。实际启动容器，使用公钥登录 root，并验证 Python 3.12.3；启动没有执行 apt 安装。

Registry 的 Docker 推送曾因凭据权限失败；重新登录后权限恢复。大镜像上传遇到存储 HTTP 跳转 403 和 OCI manifest 不兼容；本次使用标准 Registry API 复用基础层、补传新层，按 Docker schema 2 发布并核对远端摘要。此处理用于本次发布，没有修改 Docker 的全局网络或关闭 TLS 校验。

默认 SSH 镜像已发布至 `ccr-zhicheng-02/slai-cci-pytorch-ssh:25.06-20260911`，镜像名不含个人用户名。已通过 CCI 本体和复制实例两次真实 SSH 登录，并在 `/data` 创建、读回和删除测试文件；DNAT 迁移后 hostname 对应副本 UID。

另外用项目的 `plan_sync` / `sync_image` 实际推送了一个本地小镜像到 CCR，源名称和标签原样保留。推送成功后通过 CCR 管理 REST 删除测试仓库并确认镜像已不存在。该测试没有绕过上传代码或模拟 Docker 推送。

ACP 默认闲时资源已在计算池成功提交并运行。调试池曾返回 `tjInvalidQuotaTypeInAec2`，现已转成明确的配额/资源池调整提示。
